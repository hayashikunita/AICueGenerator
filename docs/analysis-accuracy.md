# 全体の候補判定とローカルAI補助

解析エンジン：0.4.0。確認日：2026-10-25。

0.6.0で歌い始めの単発音・分離漏れの除外を改善し、イントロアウトロ特化でも選択可能にしました。専用タブでは未検出時にVerseを代用しません。変更内容と検証は[イントロアウトロ特化の確認](intro-outro-mode.md)を参照してください。以下は0.4.0時点の記録です。

## 通常解析の変更

拍の先頭512サンプルだけで比較していた音の変化を、拍全体のFFTから計算します。12音のクロマ、16の周波数帯域、音量・低域を小節ごとに集約します。和音・音色・音量が同時に変わる位置を評価し、強い打音だけでフレーズの位相を決めないようにしました。

「反復整合」は、近傍の音量の平坦さを測る処理から、離れた位置の複数小節を順序ごと比較する処理へ変更しました。曲全体で同じループが続く場合には、そのことだけで特定区間の反復スコアを上げません。候補の並び順も、表示する総合スコアに合わせています。

サビのラベルがない場合は、Drop〜Break/Outro区間を弱い推定として提示し、繰り返しの裏付けが弱ければ信頼度を下げます。Dropがサビであるとは断定しません。rekordboxの既知のIntro・Chorus・Outroラベルは優先します。

## AI補助

音源分離に[HTDemucs](https://github.com/facebookresearch/demucs)を使用します。Windows/Python 3.13で動作確認した構成は以下です。

| 項目 | 使用したもの |
| --- | --- |
| PyTorch | 2.14.1+cpu |
| 推論ライブラリ | [demucs-infer](https://github.com/openmirlab/demucs-infer)、コミット`ffe0080ef96336a34e3f0ee8ba22ceaa0623a36c` |
| 分離モデル | `htdemucs`、Meta配布チェックポイント |
| ライセンス参照 | [元の実装のMITライセンス](https://github.com/facebookresearch/demucs/blob/main/LICENSE)、[チェックポイント配布情報](https://github.com/openmirlab/demucs-infer/blob/ffe0080ef96336a34e3f0ee8ba22ceaa0623a36c/demucs_infer/config/checkpoints.toml) |

学習済みモデルが行うのはボーカル・ドラム・ベース・その他への音源分離です。Intro／Chorus／Outroを分類する学習済みモデルは今回導入していません。分離したボーカル比率を区間の特徴に加え、ボーカルの開始を別途調べます。

分離ボーカルの開始には、絶対音量、ボーカル内の相対音量、ミックスに対する比率、一定時間の継続を要求します。微弱な分離漏れや短いクリックだけでは開始にしません。ただし、話し声・掛け声・分離漏れを完全に区別する処理ではありません。LRCがあればそちらを優先し、どちらからも取得できなければVerseの仮候補に戻ります。AIによるボーカル開始の信頼度は65で、正解確率ではありません。

元音源は読み取りのみです。分離処理は別のPythonプロセスで実行し、音源を外部へ送信しません。保存するのは0.1秒単位の各成分の音量です。分離音源はディスクへ書きません。モデル導入時には公開配布元から重みをダウンロードします。

## 検証と限界

- バックエンド全241件、TypeScript・Viteビルド、ChromiumのUI操作確認が通過しました。既存のStarlette/httpx非推奨警告が1件あります。
- 拍の頭が同じでも後半の和音が違う音源、独立した反復区間、単調なループ、打音と区間境界の不一致を回帰テストに追加しました。
- 分離ボーカル開始・微弱な分離漏れ・短い音の除外、LRC優先、AIキャッシュ、キャンセル、処理中の音源・グリッド変更を検証しました。
- API経由のAIジョブでも、候補を自動採用しないことと元音源を変更しないことを確認しています。
- 実曲「Lottery 4.0 (Dirty)」でCPU音源分離を実行しました。長さ約192秒、初回約110秒、分離ボーカルの開始候補は約0.7秒でした。この時刻が歌詞の始まりかは未判定です。
- 「House 3」の約14秒の音源では分離ボーカルの開始を未検出とし、処理は約13秒でした。
- 稼働中アプリのAPI経由で「Lottery 4.0 (Dirty)」の確認用解析を1件作成しました。13候補を未採用で保存し、すべて保存済みの拍位置に一致、歌い始め以外は小節頭に一致しました。実行前後で元音源のSHA-256とrekordboxの解析・Cueスナップショットが同一でした。XMLは取り込んでいません。
- UIでは通常／AI補助の切り替え、選択の保持、未準備時の通常解析、既存の採用・XML確認操作を検証しています。

これらは実装の回帰テスト・実行確認です。正解位置を付けた実曲集合での正解率、適合率、再現率は未測定です。すべての曲・ジャンルで精度が向上したと保証するものではありません。特に歌い始めの定義やサビの範囲は試聴で確認する必要があります。過去の解析結果・採用済みCueは書き換えず、新しい解析として候補を作成します。
