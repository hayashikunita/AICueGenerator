# イントロアウトロ特化の確認

解析エンジン：0.8.0。確認日：2026-10-25。

第三のタブを追加しました。指定された「アウトロ曲の終わり」は「アウトロの終わり」に統合し、指定小節目の3項目・歌い始め・ボーカルの終わりを加えて合計17項目です。フェード終端は「音がほぼ聞こえなくなる位置」を基準にしています。

0.8.0では3タブで「ボーカルの終わり」を選択できます。最後の継続する声を逆向きの包絡で調べ、短い単発音と弱い分離漏れを除き、語間の隙間と弱い末尾を考慮します。最寄りの保存済み拍へ合わせ、未検出なら省略します。LRC最終行は終了時刻ではないため使用しません。掛け声・話し声や残響は試聴が必要です。

この項目では段階解析を曲末まで続けます。開始だけの部分キャッシュは終端判定に流用せず、完全なボーカル・全ステムのキャッシュは再利用します。未選択時の早期終了は保持します。Hot／Memory／両方と色を指定でき、候補は未採用で表示します。元音源・既存Cue・プレイリストは変更しません。

## 実装の範囲

- 7種類の小節数を1〜128で独立指定し、一括入力にも対応。初期値は8小節。
- 「イントロのN小節目／N×2小節目／N×3小節目」は専用の基準値を共有。最初の小節を1と数え、8なら8・16・24小節目の小節頭を生成。イントロ終端以降は省略する。
- 区間内の間隔、区間終端・フェード終端・ファイル末尾からの逆算を、保存済みの小節頭で計算。
- Intro／Outroのフレーズを優先。区間や指定小節数が成立しなければ候補を省略し、理由を表示。
- サビ・Break・Build・Dropの判定を実行しない。歌い始め・ボーカルの終わりは追加で選択可能で、両方が未選択ならAI音源分離も実行しない。
- 通常タブのTop-kや解析単位を専用モードへ持ち込まない。間隔候補は区間全体で生成。
- Cue種類・色を項目ごとに指定し、実行時の設定をジョブへ保存。候補名とXML名に小節数を表示。
- 既存Cue・グリッド・元音源は変更せず、候補を未採用で表示。

TypeScript・ViteビルドとChromiumの操作テストも通過しました。3タブで終了のみを選ぶ操作、従来候補の保持、BOTH・Memory紫・Hot緑の事前設定と保持、未採用表示、全曲確認の進捗案内、1440px／390pxの表示を確認しました。

ボーカル分離の区間ごとの％が0へ戻り続ける見え方を修正しました。主表示を「確認済み秒数／曲全体の長さ」にし、現在の区間の％は補足に分けます。遅れて届く応答でも確認済みのバーを戻しません。Levitating (Kuu Remix) 112では約251秒の曲を全9区間で確認し、既存の解析ジョブが正常終了したことを確認しました。早期終了条件を満たさない曲では全曲確認が必要で、今回の表示修正は検出基準を変更しません。関連28件のテストで9区間を重複せず曲末で終了することと、区間の進捗取得を検証しました。

0.7.1で「従来の候補」にも歌い始めを追加選択できるようにしました。従来の5種類とその位置・信頼度・根拠を保持して、歌い始めを1候補追加します。未検出なら従来候補だけを残し、Verse先頭の代用はしません。テストではLRC優先、未選択時の従来動作、1曲・複数曲のAI連携、未採用状態、Memory紫・Hot緑のXML出力を確認しました。

バックエンド全316件、TypeScript・Viteビルド、Chromiumの操作確認が通過しました。既存のStarlette/httpx非推奨警告が1件あります。区間の確認範囲と％、ボーカル設定の保存、再起動前の旧バックエンドへ誤って全曲分離を依頼しない制限も確認しました。従来の候補と歌い始めの同時表示、チェック・Cue種類・色の保持も確認しました。

自動テストには、可変テンポ、先頭の拍ずれ、各間隔と逆算、Top-kを超える間隔候補、区間外へのはみ出し防止、フェードと急なカットの区別、末尾の孤立音、グリッド外の終端、入力制限、AI処理の省略、未採用状態、XML名を含めています。

ネイティブXMLのTotalTimeが整数秒でも、その後に音源内の有効な小節頭が存在する場合を検証しました。実音源の長さで範囲を確認し、既存XMLの属性表記は保持します。実際の音源末尾を超える候補は停止します。

Chromiumで3タブ、16項目、一括小節入力、個別小節数、Cue種類と色、設定保持、候補表示、選択ゼロ時の開始制限を確認しました。基準値3で3・6・9小節目と表示され、2倍の位置のBOTH・Memory紫・Hot赤が解析リクエストに保持されることも確認しました。1440pxと390pxで横はみ出しがなく、スクリーンショットを目視確認しました。歌い始め選択時のAI補助、Hot緑の設定保持、未採用の候補表示、AI未準備時の通常解析案内も確認しました。

## 歌い始めの精度改善（0.6.0）

0.7.0では画面のAI補助をボーカル開始用の段階解析に変更しました。30秒ずつ前後3秒の文脈とともに確認し、比較的強い声が3秒内に合計1.5秒以上続くことを確認できたら残りの分離を省略します。弱い・不明な場合は次の区間へ進み、必要なら曲末まで確認します。部分解析のボーカルを未解析区間の構造判定へ補間しません。

約192秒のLottery 4.0 (Dirty)で先頭30秒までを約43秒で確認し、0.8秒に声の開始候補を得ました。別のAI解析が同時実行中の参考値です。元音源のSHA-256とrekordboxのグリッド・フレーズ・既存Cueは前後で一致しました。実際の歌詞の開始位置との正解率は未測定です。

無音65.37秒の生成音源でも実ワーカーを実行し、3区間を曲末まで確認できることと未検出を検証しました。テストには境界付近・65秒からの声、短い先行タグ、弱い声、部分キャッシュの検証、全曲キャッシュの再利用、API経由の未採用状態とHot緑でのXML出力を含めています。全曲分離を行う既存API・過去の履歴は維持しています。

専用タブのボーカル欄から追加選択し、候補の判定方法でAI補助を利用できます。歌い始め未選択時の処理・保存済みの選択・過去の候補は保持します。

同名LRCを優先し、なければ既存のHTDemucs分離結果を利用します。声の絶対・相対音量とミックス比率を確認し、曲に合わせた比率の基準で弱い分離漏れを除外します。短い語間の隙間は許容し、最初の3秒の区間内に合計1秒以上、全体1.2秒以上の声を要求します。開始直前の0.35秒以内にある弱い音を戻って確認し、その際にも直前の背景音量を基準に分離漏れを除きます。

テストでは短い先行掛け声、一定の分離漏れ、単発の打楽器音、語間の無音、長い無音イントロ、曲頭からの声、弱い声、時間刻みの違い、不正値、未検出時のVerse代用禁止、LRC優先、AIワーカー連携を検証しました。歌い始めは小節単位に丸めず、最寄りの保存済み拍へ合わせ、検出時刻と整列後の差を根拠へ表示します。

読み取り専用の実曲確認では、Lottery 4.0 (Dirty)の分離ボーカル開始0.800秒から保存済み拍0.733秒へ整列しました。インストのHouse 3は未検出として省略しています。両曲とも元音源SHA-256とrekordboxのグリッド・フレーズ・既存Cueは前後で一致しました。実際の歌詞の開始位置との一致率は未測定で、長い掛け声・話し声は区別しきれません。既存ライブラリへの取り込みは行っていません。
