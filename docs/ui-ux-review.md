## 結果

- バックエンド：214件通過。既存のStarlette/httpx非推奨警告1件。
- フロントエンド：TypeScript・Viteビルド成功。

- 表示幅：1440px・768px・390pxでページの横はみ出しなし。PCとスマートフォンのスクリーンショットも目視確認。

## 確認した操作

| 対象 | 確認内容 |
| --- | --- |
| 曲の一括選択 | プレイリスト51件をページをまたいで取得。パス不明曲を除外。検索やプレイリストの選択を切り替えても選択曲を保持。同じ曲を重複追加しない |
| 開始前の確認 | 未解析の曲を含むと開始できず、理由を表示。対象から外すと開始できる。選択ゼロ・目的ゼロでも開始できない |
| 種類・色の事前設定 | 共通Hot Cue赤、イントロ先頭Memory Cue緑、イントロ終端は両方（Memory未設定・Hot青）、アウトロ終端Memory紫を指定。自動採用しないこと、個別・一括採用、色見本とXML、再読み込み後の設定保持を確認 |
| 終端の小節単位 | イントロ／アウトロの終わりを追加。可変テンポと先頭の拍ずれを含む実グリッドで1・4・8小節単位を検証。末尾以前の小節頭に合わせ、短い区間では位置を作らず理由を表示 |
| 既存曲への追加XML | 元曲のパス・TRACK属性・TEMPO・既存Cueの名前と色・ループ区間・Hotスロットを保持。重複は省略し、空き枠へだけ追加。音源をコピーせず元XMLの控えを保存。複数曲のうち1曲の照合に失敗すると全体の出力を停止 |
| 既存曲更新の停止条件 | 確認後のCue・色・グリッド変更、古い曲情報、上限超過、使用済みスロット、同一パスの複数候補、アクティブループ、元XMLの取り違え、確認なしの書き出しを拒否 |
| 複数曲・複数目的 | 2曲×3目的で候補を表示。共通BPMを送らず曲ごとのグリッドを利用 |
| 試聴・調整 | 候補の曲と試聴音源が一致。曲を切り替えるとプレイヤーも切り替わる。位置調整中は曲の切り替えを止め、保存・破棄後に再開できる |
| 一括採用 | 選択した候補の確認チェック後にMemory・Hot・両方で採用。保存中は曲切り替えや書き出しを止める。APIエラー後に採用状態を誤表示せず、再操作できる |
| 保存の整合性 | 1回の一括採用をDBトランザクションにまとめる。途中でDBエラーが起きても全件を取り消す。既に調整した時刻・コメント・色・スロットを保持 |
| Hot Cue制限 | 全曲合計でなく、1曲につき8件まで。2曲各8件は採用可能。既存の採用分も数える |
| Memory CueのXML出力 | 2曲に各15件を採用しても候補30件・採用30件を維持。XMLにだけ曲ごとの信頼度上位10件、合計20件を出力。対象の入れ替えと確認、表示・採用状態を変更しないこと、明示的に11件を指定すると出力前にエラーになることを確認 |
| 一括解析の失敗 | 実際の解析ワーカーで、1曲が音源不明でも他の2曲を最後まで解析 |
| XML・音源 | 2曲分を1つのXMLへ出力。各曲のHot CueをA〜Hに割り当て。同名の音源でも別々に複製し、以前の出力も保持 |
| 全曲の書き出し | 表示を1曲に絞っても、同じ解析ジョブの全曲の採用Cueを対象とする |
| モバイル操作 | 候補をカード表示し、時刻・試聴・採用を横スクロールなしで操作。クリック座標を使って候補選択・解除と確認チェックを操作 |
| Memory Cueパレット | 桃・赤・橙・黄・緑・水・青・紫・未設定を選択。矢印・Home／End・Escapeの操作。未設定を再読み込み後も保持。XMLでは未設定のMemory CueのRGB属性だけ省略し、Hot Cueの色を維持 |
| rekordbox風の表示 | 黒・グレー・青の選択表示と、波形横のMEMORY／HOT CUE一覧。両方で採用した候補が両方の一覧に表示されることを確認 |
| 既存機能 | 色の保存・XML要求、グリッド調整の確認と明示的な保存、Beat指定、歌い始めの注意表示、手動候補追加、CSV認証の回帰確認 |

## 今回修正した問題

- 複数曲の結果でも先頭曲の音源が使われる状態を修正。
- 曲切り替え時に古いプレイヤーが残る表示不具合を修正。
- 同名音源の複製と、同日の再書き出しによる上書きを防止。
- 同名曲を結果画面で区別し、書き出し確認には曲名を表示。
- スマートフォンで候補の操作が横スクロールの先に隠れる状態をカード表示へ改善。

## 再実行

```powershell
cd backend
.\.venv\Scripts\python.exe -m pytest -q
cd ..\frontend
npm run build
npm run test:ui
```

UIテストにはNode.js 22以上とChromiumを使います。Chromiumのパスは `CHROMIUM_PATH` で指定できます。WindowsではPlaywrightのキャッシュからも検出します。画面の記録は `frontend/node_modules/.cache/aicue-ux/batch-*.png` に保存します。

実際のrekordboxへXMLを取り込んだ後の表示・Cue色は未確認です。また、今回の操作確認は200曲の実音源による所要時間・負荷の測定ではありません。
