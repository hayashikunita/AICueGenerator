# rekordbox AI Cue Generator

rekordbox で解析済みの拍位置・小節頭を基準に、EDM の Intro / Break / Build / Drop / Outro のキュー候補を提案するアプリです。音源の変化も評価し、使いたい候補だけをメモリキュー・ホットキューとして採用して、rekordbox XML に書き出せます。

**基本の流れ：rekordbox で解析・保存 → このアプリで曲を選ぶ → 解析情報を確認 → 候補を生成・試聴 → 採用した Cue を XML に書き出す。**

**通常の検索・解析では既存データを変更しません。** 小節頭の調整は、対象曲と変更内容を確認して「rekordbox へ小節頭を保存」を押した場合に限り、その曲の解析ファイルへ保存します。楽曲・プレイリスト・既存 Cue は保持します。ライブラリDBは読み取り専用で、新しい Cue は別途 XML を書き出して渡します。XML の取り込みも自動では実行しません。

## 主な機能

- **曲の選択**：rekordbox ライブラリの検索、プレイリストからの選択、またはローカル音源のファイルパス指定。
- **解析と進捗表示**：rekordbox の拍位置・小節頭を利用。4 / 8 / 16 / 32 / 64 Beat はボタンで切り替え。解析を開始できない場合は理由を表示。
- **目的別Cue候補**：イントロ・アウトロ・サビの始まり／終わり・サビ終わり8小節前・歌い始めを選んで提案。試聴して位置を調整し、Hot Cue／Memory Cue／両方で採用。
- **解析情報の確認**：BPM、キー、取得した拍・小節頭・フレーズの件数、既存 Cue を表示。
- **小節頭の調整**：拍をクリックして選択し、その位置から試聴。1拍ずつの移動と選択のリセットにも対応。確認後に rekordbox の解析ファイルへ保存。自動バックアップ付き。
- **試聴**：波形とキュー候補をタイムラインに表示。マーカーをクリックして候補位置から再生。
- **候補の確認**：信頼度と判定根拠の表示、Memory Cue／Hot Cue／両方での採用、却下、判定の変更。
- **絞り込み**：種別、未判定、採用済み、信頼度が高い候補での表示切り替え。
- **解析履歴**：音源ファイル名・日時・状態の表示、曲名検索、保存済み判定の再表示。
- **書き出し**：採用したキューの rekordbox XML 出力と音源の複製、候補一覧の CSV 保存。
- **色設定**：Hot Cue／Memory Cueそれぞれの色を変更し、採用ボタン・判定・タイムラインとXMLに反映。「両方」は2色で表示。展開ごとの表示色も個別に変更。

## 動作環境

- Windows（本プロジェクトの想定実行環境）
- Python 3.11 以上
- Node.js 18 以上と npm（フロントエンドのビルドに使用）
- ブラウザ
- 解析対象の音源ファイル

通常は、rekordbox で対象曲の BPM / Grid を解析・保存してから利用します。ライブラリと ANLZ 解析ファイルを `pyrekordbox` が読み取れる環境が必要です。フレーズ解析がある場合は、その境界も利用します。連携できない場合は、ファイルパス指定による音源だけの独自解析も選べます。

音源形式の対応範囲は、インストールしたデコーダーに依存します。まず WAV で動作を確認してください。ブラウザでの試聴・波形表示にも、その音源形式への対応が必要です。

## 初回セットアップ

PowerShell を使用します。最初に、このリポジトリのルートディレクトリを開いてください。

### 1. バックエンドを準備する

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[analysis,rekordbox]"
cd ..
```

追加依存の役割は次のとおりです。

| 追加依存 | 用途 |
| --- | --- |
| `analysis` | 音源のデコード、特徴量抽出、BPM・ビートの推定 |
| `rekordbox` | ライブラリ検索、rekordbox XML 出力、プロセス検出 |
| `dev` | pytest などの開発・テスト用ツール |

XML 出力にも `rekordbox` の追加依存が必要です。暗号化されたライブラリの検索には、別途 SQLCipher 対応などの環境条件があります。

### 2. 画面をビルドする

```powershell
cd frontend
npm ci
npm run build
cd ..
```

ビルドした画面は `backend/static/` に出力されます。このディレクトリは Git 管理対象外なので、初回起動前にビルドしてください。

## 起動・終了

リポジトリのルートから実行します。

```powershell
cd backend
.\.venv\Scripts\python.exe -m app.main
```

ブラウザが自動で開きます。開かない場合は、ターミナルに表示された次の形式の URL を開いてください。

```text
http://127.0.0.1:<自動選択されたポート>/?token=<トークン>
```

- 起動したターミナルは、利用中そのままにしておきます。
- 終了するときは、ターミナルで `Ctrl+C` を押します。
- 画面を更新した場合は `frontend` で `npm run build` を実行し、アプリを再起動してください。

既定では `127.0.0.1` で待ち受ける、同じ PC 上での利用を想定したアプリです。アクセス用トークンはアプリのデータフォルダに保存され、ブラウザでも保持されます。

## 使い方

### 1. 解析する曲を選ぶ

**rekordbox から選ぶ場合**

1. 「rekordbox から」を選びます。
2. 曲名・アーティスト・アルバム・ファイル名などを入力して「検索」を押します。空欄で検索すると、最大 50 件を表示します。
3. 検索結果から曲を選び、「選択中の曲」を確認します。

空白で区切った複数の語は、すべての語を含む曲を検索します。曲に BPM 情報がある場合は、解析設定へ取り込まれます。

**プレイリストから選ぶ場合**

1. 「rekordbox から」→「プレイリストから」を選びます。
2. プレイリスト一覧から、読み込みたいプレイリストを選びます。フォルダ階層を表示するため、同じ名前のプレイリストも区別できます。
3. 登録された曲名・アーティスト・BPM を確認し、解析する曲を選びます。

通常のプレイリストは登録順に表示し、スマートプレイリストは条件に一致する曲を曲名順に表示します。曲名・アーティスト・ファイルパスで絞り込めます。50 曲を超える場合は「続きを表示」で追加取得し、プレイリストの変更後は「再取得」で更新できます。音源の場所が不明な曲も表示しますが、解析対象には選べません。

**ファイルパスから選ぶ場合**

1. 「ファイルパスから」を選びます。
2. エクスプローラーで音源を右クリックし、「パスのコピー」で取得したパスを貼り付けます。

```text
"C:\Music\track.wav"
```

引用符付きのパスも使えます。ブラウザへのアップロードではなく、バックエンドが動いている PC 上のファイルを読み込みます。

「キュー候補を探す単位」で、4 / 8 / 16 / 32 / 64 / 128 Beat を選べます。4/4 拍子を前提に、4 Beat＝1 小節、8 Beat＝2 小節、16 Beat＝4 小節です。「小節」表示にも切り替えられます。既定値は従来と同じ 64 Beat（16 小節）です。

指定した拍数ごとの境界から、曲の変化を評価してキュー候補を選びます。すべての境界へ一律にキューを置く機能ではありません。細かな変化を探す場合は 4・8 Beat、長い展開を見る場合は 32・64 Beat を指定してください。解析結果にも、実際に使った拍数と小節数を表示します。

その他の項目は、必要に応じて「解析の詳細設定」を開いて変更します。

| 設定 | 既定値・動作 |
| --- | --- |
| 解析の基準 | ライブラリ選択時は「rekordbox の解析済みデータ」。ファイルパス選択時は「音源だけで独自解析」 |
| BPM | rekordbox 基準ではグリッド内の BPM を使用。独自解析では空欄なら推定、手動指定も可能 |
| キュー候補を探す単位 | 64 Beat（16 小節）。4 / 8 / 16 / 32 / 64 / 128 Beat から選択 |
| 種別ごとの候補数 | 3 件。1 / 2 / 3 / 5 / 10 から選択 |
| コンテンツ ID | ライブラリ選択時は自動入力。空欄ならファイルパスを使用 |

「解析を開始 →」を押すと、結果画面に進捗が表示されます。解析履歴から以前の結果を開くこともできます。履歴に表示する曲名は、音源のファイル名です。

### rekordbox で先に楽曲解析する必要はありますか？

既定のライブラリ選択では、先に rekordbox で BPM / Grid の解析を行い、結果を保存してください。曲を選ぶと、このアプリが解析済みの拍位置・小節頭を確認します。未解析・解析ファイルなし・読み取り失敗の場合は理由を表示し、この方式での開始を止めます。「解析情報を再取得」で再確認できます。

保存済みグリッドを使うため、先頭拍が音源の 0 秒からずれている場合や、途中で BPM が変化する場合もその拍時刻を基準にします。フレーズ情報があれば、フレーズ先頭から指定した 4 / 8 / 16 Beat などの単位で候補位置を探します。フレーズ情報がない場合も、取得した小節頭を使って生成し、画面に未取得であることを表示します。Drop / Break などの候補種別は、音源の変化からアプリが推定します。

| rekordbox の情報 | このアプリでの利用 |
| --- | --- |
| BPM / Grid | 拍ごとの時刻と小節頭を Cue 候補の基準に使用 |
| フレーズ | 区切りの拍位置を候補探索に使用。目的別CueではIntro／Chorus／Outro等のラベルも使用 |
| キー | 取得できたキーを画面に表示 |
| 既存 Cue | 参照用に表示。新規候補の採用・XML 出力には自動で含めない |
| Vocal | 開始時刻の読み取りは未対応。歌い始めは同名LRCの時刻、なければVerse先頭を仮候補として使用 |

「解析の詳細設定」で「音源だけで独自解析」を選んだ場合は、事前の rekordbox 解析は不要です。この場合の BPM・拍推定は独立した処理です。API も互換性のため `analysis_source` 未指定時は `AUDIO` を使用します。rekordbox 基準では `analysis_source: "REKORDBOX"` と、登録済みの `content_id`・音源パスを指定してください。

実行ごとに、使ったグリッド・フレーズ・既存 Cue の概要をこのアプリ内の履歴へ保存します。rekordbox でグリッドを変更して再実行した場合は、以前の結果と混ぜずに保存します。

### 作りたい位置を指定して、自動候補からCueを作る

1. 曲を選び、「作りたいCueの位置」→「目的から選ぶ」を押します。
2. 必要な位置をチェックします。すべて選ぶ／解除もできます。1項目以上選択してください。
3. 解析を開始します。候補はまだ採用されていません。指定した位置が特定できない場合は、理由を表示して候補を省略します。
4. 候補一覧の「試聴」で位置を確認します。「位置を調整」を開くと、秒数入力、1拍／1小節ずつの移動、最寄りの拍／小節頭への整列ができます。
5. 調整した位置を試聴してから、Hot Cue／Memory Cue／両方で採用します。調整のプレビューだけでは、採用状態やXMLを変更しません。保存後の画面・履歴・CSV・XMLには調整後の位置を使います。判定を変更しても調整位置を保持します。

| 指定する位置 | 候補の作り方 |
| --- | --- |
| イントロの始まり | rekordboxのIntro先頭を優先。ラベルがなければ最初の有音部分以降の小節頭を推定 |
| アウトロの始まり | rekordboxのOutro先頭を優先。ラベルがなければ音源終盤の音量低下などから推定 |
| サビの始まり・終わり | rekordboxのChorus区間を優先。連続するChorusは1区間として扱う。既知のラベルがない場合のみ、Drop〜Break/Outroの区間を弱い推定として使い、「サビとは限らない」と表示 |
| サビの終わりから8小節前 | サビ終了の小節頭から、解析済みグリッドの小節頭を8個戻る。BPMから固定秒数を引かない。8小節より短い区間や範囲外の終了位置からは生成しない |
| 歌い始め | 音源と同じ名前の`.lrc`があれば最初の歌詞時刻を最寄りの拍へ整列。なければ最初のVerse先頭を低い信頼度の仮候補として提案 |

**歌声の検出・歌詞の認識は行っていません。** rekordboxのVocal開始時刻は現在取得できず、Verse先頭も実際の歌い始めとは限りません。LRCはUTF-8の時刻付き歌詞を読み取り、`[offset:...]`に対応します。歌詞ファイルも書き換えません。LRCもVerseもなければ歌い始めを推測して埋めず、未検出と表示します。LRCの変更時はキャッシュを区別します。

自動で見つからなかった位置は、結果の「見つからなかった位置を、試聴して候補に追加」から補えます。再生位置または秒数を指定し、拍／小節頭へ合わせて確認用の候補を追加してください。手動追加も自動採用しません。別の履歴と解析結果を共有している場合は、その結果を複製して追加し、他の履歴・採用内容を保持します。

候補は推定・解析ラベルに基づく提案で、楽曲の正解を保証しません。位置を調整した候補の元の信頼度・根拠は、自動解析位置についての情報です。必要な候補だけを採用し、従来どおりXMLを書き出します。既存ライブラリ・Cueへの直接追加は行いません。

従来のIntro End／Break／Build／Drop／Outro候補を使う場合は「従来の候補」を選んでください。APIは`params.cue_targets`に`INTRO_START`、`OUTRO`、`CHORUS_START`、`CHORUS_END`、`CHORUS_END_MINUS_8_BARS`、`VOCAL_START`の配列を指定します。省略・nullなら従来の候補です。フレーズのラベルの解釈は[PSSIのmood別定義](https://github.com/Deep-Symmetry/crate-digger/blob/main/src/main/kaitai/rekordbox_anlz.ksy)を参照しています。

### rekordbox で小節頭を変更した場合

このアプリは、解析ファイルに記録された「1 拍目」の位置を小節頭として使用します。rekordbox 側で拍の時刻を動かさずに小節頭だけを変更した場合も、保存済みデータを再取得して反映できます。

1. rekordbox 側で行った編集を保存します。
2. このアプリで同じ曲を選び、「解析情報を再取得」を押します。
3. 「解析を開始 →」で新しい候補を生成します。

再取得は次の解析に使うデータの確認です。表示中の過去の候補は自動で更新せず、再実行した結果を別の履歴に保存します。

### このアプリから小節頭を変更する

1. ライブラリから対象曲を選び、「小節頭を調整」を開きます。
2. 先頭8拍のボタンから、小節頭にしたい拍をクリックします。赤い「1」が新しい小節頭です。選択欄や「1拍前」「1拍後」からも調整でき、「元に戻す」で選択をリセットします。
3. 「選んだ小節頭から試聴」で音を確認します。通常の再生コントロールでシークや停止もできます。試聴は解析ジョブを作らずに利用でき、選択・試聴だけでは保存されません。音源形式によってはブラウザで再生できない場合があり、その際は理由を表示します。
4. rekordbox を終了してから「変更内容を確認」を押します。対象曲と、曲全体のどの拍を新しい1拍目にするか確認します。「調整に戻る」で確認を取り消して調整し直せます。
5. 「rekordbox へ小節頭を保存」を押します。元の解析ファイルを自動バックアップしてから保存し、保存先を表示します。有効期限が切れた場合は保存を止め、再確認の案内を表示します。
6. rekordbox を起動して曲を読み込み直し、GRIDを確認してください。このアプリで新しい候補を作るには、同じ曲の解析を開始します。

曲全体の拍番号を同じだけずらす機能です。拍時刻・BPM・音源・曲名・プレイリスト・既存 Cue・フレーズ・波形は維持します。途中の区間だけを調整する機能や、拍の時刻を移動する機能は含みません。

保存確認は10分間有効です。確認後に解析ファイルが変わった場合、rekordbox が起動中の場合、終了状態を確認できない場合、未対応の形式や解析ファイル間の不一致がある場合は保存を止めます。rekordbox の終了時にもデータが保存されることがあるため、終了後に改めて変更内容を確認してください。解析ファイルへの保存はコピーを使って検証しています。実際の rekordbox の画面表示は、保存後の読み込み直しで確認してください。

バックアップは `grid-backups/<操作ID>/` に保存します。`manifest.json` に対象ファイルと変更前後のSHA-256、処理状態を記録します。通常の保存失敗では、変更済みファイルを元へ戻します。復元失敗を表示した場合や保存中にアプリが終了した場合は、rekordbox を終了したまま、この記録とバックアップを確認してください。手動で戻すときは、対象ファイルが記録の変更後SHA-256と一致し、その後の編集がないことを確認し、`backup` のファイルを記録の `original` の場所へ戻します。

### 2. 試聴してキューを採用する

1. タイムラインの再生ボタンやキューマーカーで音源を試聴します。波形部分をクリックすると、再生位置を移動できます。
2. 候補一覧で、種別・時刻・信頼度を確認します。「根拠」を開くと、判定に使用した情報を確認できます。
3. 使いたい候補を「Memory Cue」「Hot Cue」「両方」のいずれかで採用し、不要な候補は「却下」します。

| 判定 | 用途 |
| --- | --- |
| Memory Cue | 曲の展開やミックス位置の目印となるメモリキューとして採用 |
| Hot Cue | 再生位置をすぐ呼び出したい場所をホットキューとして採用 |
| 両方 | 同じ位置に Memory Cue と Hot Cue を 1 件ずつ登録 |
| 却下 | 書き出し対象から除外 |

採用・却下は保存され、履歴を開き直しても確認できます。後から別の判定に変更することもできます。同じ曲の中で、目印は Memory Cue、Drop は Hot Cue といった使い分けができます。

候補数が多い場合は「表示」と「種別」で絞り込んでください。Memory Cue／Hot Cue 別の採用済み表示にも対応し、「両方」を選んだ候補はどちらにも表示されます。狭い画面では、表を横にスクロールすると操作ボタンが表示されます。

「🎨 キュー色設定」を開くと、Hot CueとMemory Cueそれぞれの色を選べます。採用ボタン・判定・件数の色見本・タイムライン・書き出し内容の確認に反映し、「両方」は2色で表示します。採用前のタイムラインは、従来のDrop／Breakなどの展開色を使います。暗い色や明るい色でも採用ボタンの文字が読めるよう文字色を調整します。

設定はブラウザのlocalStorageへ保存し、同じURLの画面を再読み込みしても維持します。展開ごとの色設定は保持し、Hot Cue／Memory Cueの設定と別々に変更できます。「既定」はその項目だけを戻し、「すべて既定に戻す」は両方の設定を戻します。

XMLの書き出し時に、現在のHot Cue／Memory Cueの設定色を`POSITION_MARK`の`Red`・`Green`・`Blue`へ記録します。「両方」は別々の色の2キューになります。色を変えても採用・却下や時刻・スロットを変更せず、次に書き出すXMLへ適用します。既存のrekordbox Cueの色を直接書き換える操作は行いません。

XMLにRGBが記録されることはテストしますが、実際のrekordboxへの取り込み後の表示は未検証です。特にMemory Cueの色が反映されることは保証できないため、画面と書き出し結果にも確認の案内を表示します。読み込み互換性の参考：[rekordboxのXML仕様](https://cdn.rekordbox.com/files/20200410160904/xml_format_list.pdf)、[RGB付きHot Cueの例](https://forums.pioneerdj.com/hc/en-us/community/posts/205639093-Convert-Hot-Cues-to-Memory-Cues)。

### 3. rekordbox XML を書き出す

1. 1 件以上の候補を採用します。
2. 「rekordbox XML を書き出し」を押します。
3. 画面に表示された保存先と、書き出した楽曲・キューの件数を確認します。
4. 出力された `rekordbox.xml` を rekordbox の XML 読み込み機能で取り込みます。

Memory Cue と Hot Cue は、同じ XML にそれぞれの種類で出力されます。画面には種類ごとの件数と合計キュー数を表示し、「両方」は 2 キューとして数えます。Hot Cue は曲中の時刻順に A〜H の空き枠へ自動割り当てします。現在の XML 出力は 1 曲につき Hot Cue 8 件までで、超える場合はエラーを表示します。Memory Cue に変更するか、採用数を減らしてください。

出力先は、既定で次の場所です。

```text
%USERPROFILE%\.aicuegenerator\exports\YYYYMMDD\
├── rekordbox.xml
└── 複製した音源ファイル
```

XML は複製先の音源を参照します。元の音源ファイルは変更しません。複製できなかった音源はスキップされ、結果画面に理由が表示されます。

同じ日付のフォルダへ再度書き出すと、`rekordbox.xml` と同名の音源ファイルは上書きされます。以前の出力を残したい場合は、再出力前にフォルダを別の場所へコピーしてください。

「CSV を保存」では、候補一覧をダウンロードできます。CSV は確認・記録用で、キューの受け渡しには XML を使います。

### 既存ライブラリの保護

「書き出すキューを確認」では、採用した候補の種類・時刻を確認できます。判定を変更した場合や別の解析結果を開いた場合、表示中の内容はリセットされます。

ライブラリ参照の DB 接続には `PRAGMA query_only=ON` を設定し、DBへの書き込みを禁止しています。小節頭を明示的に保存するときだけ、解析ファイルの既知の拍番号フィールド（PQTZの各拍、PQT2の先頭・末尾）を変更します。ファイル全体の再構築を避け、PQT2の未解明の本体を含め、他のバイトはそのまま保持します。保存前のバックアップ・データ変更検出・ファイル単位の置き換え・保存後検証を行います。既存の曲名・配置・プレイリスト・Cue を整理し直す処理はありません。Cueの直接書き込み API は引き続き要求を拒否します。

## データの保存先

| データ | 既定の保存先 |
| --- | --- |
| 解析履歴・候補・採用／却下・監査ログ | `%USERPROFILE%\.aicuegenerator\app.db` |
| アクセス用トークン | `%USERPROFILE%\.aicuegenerator\token` |
| XML と複製音源 | `%USERPROFILE%\.aicuegenerator\exports\YYYYMMDD\` |
| 小節頭保存前の解析ファイル・復元記録 | `%USERPROFILE%\.aicuegenerator\grid-backups\<操作ID>\` |
| ブラウザ側のトークン・表示色 | ブラウザの localStorage |

アプリの保存先は `AICUE_DATA_DIR` で変更できます。履歴を引き継ぐ場合は、アプリを終了してからデータフォルダをバックアップ・移行してください。音源はパスで参照するため、元の音源を移動すると試聴や再解析ができなくなります。

## 設定

環境変数は `AICUE_` プレフィックスで指定します。バックエンドを起動する作業ディレクトリの `.env` でも設定できます。

| 環境変数 | 既定値 | 用途 |
| --- | --- | --- |
| `AICUE_HOST` | `127.0.0.1` | 待ち受けアドレス |
| `AICUE_PORT` | `0` | 待ち受けポート。`0` は空きポートを自動選択 |
| `AICUE_OPEN_BROWSER` | `true` | 起動時にブラウザを開くか |
| `AICUE_DATA_DIR` | ユーザーホーム内の `.aicuegenerator` | アプリデータの保存先 |
| `AICUE_TOKEN` | 未指定 | アクセス用トークンを指定。未指定なら生成・保存 |
| `AICUE_REKORDBOX_DB_PATH` | 未指定 | 検索に使用する rekordbox データベースのパス |
| `AICUE_REKORDBOX_KEY` | 未指定 | rekordbox データベースの復号鍵 |

たとえば、ポートを固定してブラウザの自動起動を止める場合は、起動前に設定します。

```powershell
$env:AICUE_PORT = "8000"
$env:AICUE_OPEN_BROWSER = "false"
```

## 困ったとき

| 症状 | 確認すること |
| --- | --- |
| 起動しても画面が出ない | `frontend` で `npm ci` と `npm run build` を実行し、バックエンドを再起動する |
| 「トークンがありません」や認証エラーになる | 起動時に表示された `?token=...` 付きの URL を開き直す |
| rekordbox の曲を検索できない | `rekordbox` の追加依存とライブラリの読み取り環境を確認する。連携できない場合はファイルパスから解析する |
| 解析が失敗する | 音源のパス・存在・読み取り権限と `analysis` の追加依存を確認する。まず WAV で試す |
| 解析済みデータで開始できない | rekordbox で BPM / Grid を解析・保存し、「解析情報を再取得」を押す。ANLZ ファイルの存在と読み取り環境も確認する |
| 波形が出ない・試聴できない | 元の音源の場所とブラウザの音源形式への対応を確認する |
| XML 書き出しが押せない | 候補を 1 件以上採用し、判定の保存完了を待つ |
| XML 書き出しに失敗する | `rekordbox` の追加依存、保存先の空き容量・書き込み権限、元の音源の存在を確認する |
| Cueの直接書き込みが利用できない | 現在は無効。XML 書き出しを利用する |
| 小節頭を保存できない | rekordbox を終了後、変更内容を再確認する。解析形式・保存権限・psutilによるプロセス確認も必要 |
| 変更した画面が反映されない | `npm run build` 後にアプリを再起動し、ブラウザを再読み込みする |
| 開発画面で API に接続できない | バックエンドのポートと Vite のプロキシ先を一致させ、開発画面にもトークンを渡す |

## 開発

### フロントエンド開発モード

最初のターミナルで、リポジトリのルートからバックエンドを起動します。

```powershell
cd backend
$env:AICUE_PORT = "8000"
$env:AICUE_OPEN_BROWSER = "false"
.\.venv\Scripts\python.exe -m app.main
```

別のターミナルで、リポジトリのルートから Vite を起動します。

```powershell
cd frontend
npm run dev
```

Vite が表示した URL を開き、バックエンドの起動ログにあるトークンをクエリに付けます。

```text
http://127.0.0.1:5173/?token=<バックエンドのトークン>
```

Vite は `/api` と `/ws` を、既定で `http://127.0.0.1:8000` に転送します。バックエンドを別のポートで起動する場合は、Vite 起動前に `VITE_BACKEND` を設定してください。

```powershell
$env:VITE_BACKEND = "http://127.0.0.1:54321"
npm run dev
```

### テスト・ビルド

バックエンドのテストは、`backend` ディレクトリで実行します。

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[dev,analysis,rekordbox]"
.\.venv\Scripts\python.exe -m pytest -q
```

テストは、一時ディレクトリのアプリデータを使用します。

フロントエンドの型チェックと配信用ビルドは、`frontend` ディレクトリで実行します。

```powershell
npm run build
```

### 構成・技術スタック

```text
AICueGenerator/
├── backend/
│   ├── app/          # FastAPI、音声解析、SQLite、rekordbox 連携
│   ├── tests/        # バックエンドのテスト
│   ├── spikes/       # rekordbox 連携の実機検証
│   └── static/       # フロントエンドのビルド出力（Git 管理対象外）

│   └── src/          # React、TypeScript、CSS

```

- バックエンド：Python / FastAPI / SQLite
- フロントエンド：React / TypeScript / Vite
- 音声解析：NumPy / SciPy / soundfile / librosa
- rekordbox 連携・XML 出力：pyrekordbox

### 主な API

HTTP API は、原則として `Authorization: Bearer <トークン>` を付けて呼び出します。音源ストリーミングと WebSocket は、クエリの `token` にも対応しています。

| メソッド | パス | 用途 |
| --- | --- | --- |
| GET | `/api/v1/health` | ヘルスチェック |
| GET | `/api/v1/diagnostics` | 連携状態の確認 |
| GET / POST | `/api/v1/jobs` | 解析履歴の取得 / 新規解析 |
| GET | `/api/v1/jobs/{job_id}` | 解析状態の取得 |
| POST | `/api/v1/jobs/{job_id}/cancel` | 解析のキャンセル要求 |
| GET | `/api/v1/jobs/{job_id}/tracks` | 解析対象の音源情報 |
| GET | `/api/v1/jobs/{job_id}/candidates` | 候補と保存済み判定の取得 |
| POST | `/api/v1/candidates/{candidate_id}/decision` | 候補の採用・却下 |
| POST | `/api/v1/candidates/{candidate_id}/preview-position` | 保存せず位置を調整。`time_ms`・`snap_to: BEAT / BAR`・単位数`step`を指定 |
| POST | `/api/v1/jobs/{job_id}/candidates/manual` | 完了済み結果へ確認用の候補を追加。`track_id`・`target`・`time_ms`・`snap_to`を指定 |
| GET | `/api/v1/rekordbox/tracks` | ライブラリ検索 |
| GET | `/api/v1/rekordbox/tracks/{content_id}/analysis` | 解析済みグリッド・フレーズ・キー・既存 Cue の概要。任意の `path` で登録音源との一致を確認 |
| GET | `/api/v1/rekordbox/tracks/{content_id}/grid?path=...` | 小節頭のプレビュー（書き込みなし） |
| POST | `/api/v1/rekordbox/tracks/{content_id}/grid/plan` | 小節頭の変更確認。`path` と `first_beat: 2 / 3 / 4` を指定 |
| POST | `/api/v1/rekordbox/tracks/{content_id}/grid/apply` | 確認済みの `plan_id` を指定して小節頭を保存 |
| GET | `/api/v1/rekordbox/playlists` | プレイリスト名・フォルダ階層の取得 |
| GET | `/api/v1/rekordbox/playlists/{playlist_id}/tracks` | プレイリスト内の曲名・アーティスト・BPM の取得。`query` / `offset` / `limit` に対応 |
| GET | `/api/v1/tracks/{track_id}/audio` | 音源ストリーミング |
| GET | `/api/v1/rekordbox/tracks/{content_id}/audio?path=...` | 選択中の登録音源を試聴。解析ジョブ不要。登録パスとの一致・認証・Rangeに対応 |
| GET | `/api/v1/jobs/{job_id}/export.csv` | 候補一覧の CSV |
| POST | `/api/v1/write/plan` | 書き込み計画の作成 |
| POST | `/api/v1/write/execute` | 書き込み要求（現在は拒否） |
| POST | `/api/v1/write/export-xml` | XML と複製音源の出力。任意の`cue_colors: {"MEMORY":"#112233", "HOT":"#ffaa00"}`で種類ごとのRGBを指定。省略時は従来どおり色指定なし |
| WebSocket | `/ws/jobs/{job_id}` | 解析進捗の通知 |
